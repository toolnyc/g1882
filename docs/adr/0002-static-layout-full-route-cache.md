# Static Layout and Full-Route Cache

**Context**: All frontend pages render dynamically on every request, even when the content has not changed. The root cause is that the shared layout (`src/app/(frontend)/layout.tsx`) calls `draftMode()` and `getAuthStatus()` — dynamic functions in Next.js — to drive the `<AdminBar>` editor overlay and the `<NewsletterGate>` admin bypass. In Next.js App Router, any dynamic function call in a shared layout propagates dynamic rendering to every child route. Additionally, the individual data fetchers (`getCachedGlobal`, `getCachedArtists`, etc.) each call `draftMode()` internally, which re-opts every page into dynamic rendering even after the layout concern is resolved. The result is that Payload's `revalidatePath` hooks invalidate the data cache but the full-route cache is never used, so there is no HTML caching at all — every visitor triggers a full Node.js render.

**Decision**:
1. Move the `draftMode()` and `getAuthStatus()` calls out of the layout and into a new `<AdminBarIsland>` async server component. Wrap it in `<Suspense fallback={null}>` in the layout so its dynamic behavior does not propagate to the parent route.
2. Remove the `isAdmin` server-side prop from `<Providers>`. The `<NewsletterGate>` component resolves admin status client-side via `/api/users/me`, relying on its existing `!isReady` guard to prevent flicker.
3. Remove `draftMode()` from all data fetchers. Add a `draft` boolean parameter to each `getCached*` function. Pages call `draftMode()` once at the top level and pass the result to every fetcher. `generateMetadata` functions always pass `draft = false`.
4. Remove `export const dynamic = 'force-dynamic'` from all public pages. Add `export const revalidate = false` to opt into indefinite full-route caching invalidated exclusively by Payload's `revalidatePath` hooks.
5. Change `revalidate: 60` in all `unstable_cache` calls to `revalidate: false`, making the data cache also indefinite and hook-driven.

**Why**: Removing dynamic functions from the layout and data fetchers allows Next.js to cache the full rendered page output. Visitors receive pre-rendered HTML without triggering a Node.js render. Content freshness is maintained entirely by the existing Payload revalidation hooks, which already call `revalidatePath` and `revalidateTag` on every publish and delete event. Draft mode continues to work correctly for editors: the `draftMode()` cookie bypasses the full-route cache automatically (Next.js never serves cached responses to draft-mode requests), and data fetchers bypass `unstable_cache` when `draft = true`.
